m3note_keystore_profile (Android.mk, step 5)

Marker file. The module exists for its LOCAL_POST_INSTALL_CMD: it removes the
keystore.mt6755.so / keystore.mz6755_66_n.so -> libMcTeeKeymaster.so links
created by m681_vendor_hal_symlinks and links the same library as
keystore.m681tee.so.

hw_get_module_by_class("keystore") tries ro.hardware.keystore first, then
ro.hardware / ro.product.board / ro.board.platform / ro.arch, then "default".
libinit sets ro.hardware.keystore=m681tee on m681 only, so:
  m681: keystore.m681tee.so -> Trustonic keymaster.
  l681: no keystore module -> android.hardware.keymaster@3.0-impl falls back
        to its software keymaster.

On l681 the Trustonic keymaster hangs keystore (the m681 keymaster TA does not
open on the L681H TEE). Without any keymaster HAL Pie's keystore aborts, so the
-impl stays on both revisions.
